# GOAL
- Update Window to work between two other Rooms, instead of using a dummy exterior. 
- Apply this kind of window to the one between LivingRoom and FrontDeck

# RELEVANT FILES
- `GeometryBuilder\Shapes\Furniture\WindowJunction.cs` - class which renders a window, but currently only works from one side
- `GeometryBuilder\Shapes\WorldSegments\UpstairsWorldSegment.cs` - sets up the segment containing LivingRoom
- `GeometryBuilder\Shapes\WorldSegments\OutsideWorldSegment.cs` - sets up the segment containing FrontDeck

# NOTES
- currently, the WindowJunction class creates a "dummy exterior". However, we want a mode where the other side is a regular Room
- we don't want to change the behavior of all windows, it should be easy to opt in or out of this behavior
- we use "PlaceHolder" shapes when a shape in one WorldSegment needs to refer to a shape in another WorldSegment. 
	- the placeholder is replaced with the actual room when the world is generated

# ACCEPTANCE CRITERIA

2. the window is visible from both sides, not just from LivingRoom
3. the LivingRoom side still has the curtain rod and curtains.
4. no additional geometry is needed on the FrontDeck side at this time
5. the window should be an actual connection, regardless of whether or not the two rooms are already connected in a different way

# RESEARCH NOTES

## Current Window Implementation

### Window Constructor Behavior
The Window class (in WindowJunction.cs) currently:
1. Creates a thin junction room (0.2f depth) positioned in the parent room's wall
2. Creates a dummy exterior room via CreateDummyExterior() with:
   - WindowExterior class that extends Room
   - Fixed size slightly larger than the window opening
   - FixedAmbientLight = LightIntensity.VeryBright for outdoor lighting effect
   - HasPathfindingWaypoint = false (non-navigable)
3. Uses AddConnectingRoomWithJunction() to connect: parent room → window junction → dummy exterior
4. Adds visual elements to the interior side only:
   - Windowsill (bottom slice with overhang)
   - Curtain rod (Cylinder positioned above window)
   - Two curtains (one on each side of the rod)

### How Room Connections Work
- RoomConnection records specify connections between rooms and a wall side
- During rendering (Room.BuildInternal()), RemoveSurfaceRegion cuts openings in walls based on the connected room's size/position
- The cutout calculation in RoomConnection.CalcCutoutPlacement() determines the opening dimensions
- Junction rooms (like DoorJunction and Window) act as thin connecting spaces between two other rooms

### PlaceholderShape System
- PlaceholderShape<T> is a non-rendered shape that acts as a proxy for a room in another WorldSegment
- During world initialization, WorldSegmentAnchorProcessor.ProcessPlaceholders():
  1. Finds all placeholders and locates real shapes (matches by type T and optional Tag)
  2. Validates position/size match
  3. Replaces placeholder with real room in all connections, graphs, and lighting

### Current Usage Pattern
- Kitchen, Bedroom, LivingRoom all create windows with dummy exteriors
- All windows use the same constructor that creates WindowExterior internally

### Cross-WorldSegment Connections (Door Example)
- UpstairsWorldSegment: LivingRoom → DoorJunction (tagged FrontDoor) → PlaceholderShape<FrontDeck>
- OutsideWorldSegment: FrontDeck → PlaceholderShape<DoorJunction> (tagged FrontDoor)

## Implementation Plan
1. Add a boolean parameter to Window constructor specifying if we should create a dummy exterior
2. When true, we create a DummyExterior and connect to it. When false, we do nothing and trust that the caller will take care of connecting the window to the other side.
3. For LivingRoom→FrontDeck: Create Window with PlaceholderShape<FrontDeck>, add matching placeholder in OutsideWorldSegment
4. Window geometry (sill, curtains) remains on interior side only
5. Window opening appears on both sides automatically via RemoveSurfaceRegion
