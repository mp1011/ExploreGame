# PROBLEM STATEMENT
- The game world is intended to be a connected world, made of individual segments.
- Currently, each segment is positioned relative to other segments
- However, as the world grows bigger, it would mean we can't load the later segments without also loading the rest of the whole game world

# SOLUTION
- when each WorldSegment is loaded, it is positioned against the world origin
- specific Shapes are designated as "anchors", which are shared between multiple segments
- when a WorldSegment is loaded, we use anchors to move the new WorldSegment into the proper place
	- this means the absolute position of each room may be different depending on which segment is loaded first
	- however the RELATIVE position will be the same

# TECHNICAL OVERVIEW
- each WorldSegment will expose a list of "Anchor" shape types which are shapes shared by multiple segments
- when we load a WorldSegment, we check if any of those Anchor shapes were already loaded
	- if so, we move every shape in the WorldSegment such that its own Anchor shape overlaps the previously loaded anchor
	- then, the new anchor shape gets replaced by the previously loaded one, and all connections are replaced

# TESTING
- we don't need specific tests for this change. 
- we'll use the existing test suite to determine if this works correctly

# TECHNICAL DETAIL
1. When a new WorldSegment is loaded, we go through its Anchor shapes types and check if there's an instance already loaded
2. If so, we check the delta between the loaded anchor shape and the current
3. As a sanity check, the size of original and new anchor shapes are compared. If they are not the same, we raise an error.
3. The shapes and geometry of the new segment are translated to match the original anchor shape
4. If there are multiple anchors, we check the rest of them.
	- however, since we only expect one translation, we expect no additional translations to occur
	- should we find that another anchor is trying to move the segment again, we throw an error as it means there is some contradiction of anchors

# SECOND ROUND ITERATION
- the problem with shared anchor shapes is the geometry has to be exactly the same for both WorldSegments
- however, geometry depends on what rooms connect to it. 
	- specific example, in UpstairsWorldSegment, the UpstairsHall connects to upstairsHall.NorthHall and upstairsHall.SouthHall
	- but in BasementWorldSegment, UpstairsHall connects to the DoorJunction of the basement stairs
- instead of thinking of anchors as shared regions, we instead use a model where one WorldSegment has the "real" shape and the other has a Placeholdder
- I've created a new class, PlaceHolderShape<T>. This is a shape meant to anchor to a real shape in the other WorldSegment
	- PlaceHolderShape matches via a type parameter T (the placeholder doesn't actually reference T at all).
	- in addition, a "Tag" may be provided if the type parameter alone isn't enough

## Changes for Round 2
1. OLD - individual world segments would be moved so that they line up with previously loaded segments
   NEW - all world segments created at same objective position, using hard-coded positions
2. OLD - world segments would share shapes, and only the first loaded one would be used
   NEW - each shape exists only in one world segment. Other world segments that reference it will create a PlaceholderShape in its place
3. OLD - world segments held a list of anchor shape types
   NEW - logic is based on PlaceholderShapes

## New Process for Round 2
1. In WorldSegmentActivationManager -> ActivateSegmentAndNeighbors, first we load each world segment
2. Then, we look for PlaceholderShapes. For each, we match it with a real shape
	- matching is done via the type parameter of PlaceHolderShape, plus the Tag if it is present
	- if no match is found, raise an error. Placeholders must always have a match
3. compare the size and position of the placeholder and real shape
	- if they don't match, raise an error containing the shape, real size, and real position, so that we can update the hard-coded position
	of the placeholder shape
4. replace the placeholder with the real shape in the following places
	- parent/child relations
	- RoomConnection
	- RoomGraph
	- WaypointGraph
	- _lightingCalculator
