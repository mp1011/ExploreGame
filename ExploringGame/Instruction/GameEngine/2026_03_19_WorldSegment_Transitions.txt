# GOAL
Dynamically load and unload WorldSegments in order to have a seamless, connected world.

# CONTEXT
- WorldSegment: a region of the game world
	- WorldSegments are organized so that the player will only be able to see at most two at any time. 
	- however, more than 2 may be loaded for easier transitions
- LoadedLevelData: contains the WorldSegments currently loaded
	- LevelData: information about a single loaded WorldSegment, including its geometry buffers and Active Objects

# SUB-GOALS
1. At any time, only the WorldSegment the player is in, and any WorldSegments neighboring it, will be available in LoadedLevelData
	- this requires establishing which WorldSegments are connected to eachother
2. Once computed, a WorldSegment will remain in memory, thanks to the ServiceContainer
	- in a later update, we'll add logic to remove WorldSegment's from memory that are no longer needed, but this is out of scope for this change
	

# INFORMATION
World Segment Connections:
	BasementWorldSegment connects to UpstairsWorldSegment (both ways)
	Upstairs WorldSegment connects to OutsideWorldSegment (both ways)

	- this can be a property directly on WorldSegment. 
	- However, this can't simply be a list of other WorldSegments as that would force the entire game world into memory at once.
