# GOAL
Building upon the basic skybox, create a dome shape to more realistically represent a sky, complete with a wrapping texture

# FILES TO READ
- Agent Docs\Skybox_Implementation_Guide.md

# TESTING
- we'll use manual testing
- we previously created TestMaps.SkyboxTest() which let us test a cube-based skybox
- create a similar class for creating and testing a dome-based skybox
- update Program.cs to load this new test map

# NEED TO KNOW
- we have a TriangleMaker class with a BuildEllipsoid method that can build a sphere. We only want a dome.
    - For simplicity, we can just use BuildEllipsoid and remove any triangles from the bottom half
- we'll need a new Theme in Texture\Theme.cs to hold the sky texture
    - the sky texture graphic is called "sky"
    - the sky texture is meant to be horizontally repeating, but not vertically
    - unlike other textures, we're not using regions for the sky texture. The whole texture should be mapped onto the triangles

# IMPLEMENTATION PLAN

## Step 1: Add Sky Texture Support to Theme.cs
**File**: `ExploringGame\Texture\Theme.cs`

Create a new `SkyTheme` class that:
- Inherits from `Theme`
- Sets appropriate `TextureSheetKey` (use existing sheet or add new one if needed)
- Configures MainTexture to use the "sky" texture graphic
- Sets TextureStyle to HorizontalRepeat (horizontally repeating, not vertically)
- Maps the entire texture onto the geometry without using texture regions

## Step 2: Create SkyDome Skybox Class
**File**: `ExploringGame\GeometryBuilder\Shapes\Skyboxes\SkyDome.cs` (new file)

Create a new skybox class that:
- Inherits from `SkyboxShape`
- Implements the singleton pattern (static Instance property)
- Sets Theme to the new SkyTheme
- In `BuildInternal()`:
  - Call `TriangleMaker.BuildEllipsoid(this)` to generate sphere triangles
  - Filter out triangles from the bottom half (where Y < center.Y)
  - Return only the top hemisphere triangles (the dome)

## Step 3: Create Helper Method in TriangleMaker (Optional)
**File**: `ExploringGame\Services\TriangleMaker.cs`

Consider adding a `BuildDome()` method that:
- Wraps BuildEllipsoid logic
- Automatically filters bottom-half triangles
- Makes code cleaner and reusable
- Alternative: Keep filtering logic in SkyDome.BuildInternal() if this is the only use case

## Step 4: Create SkyDome Test Map
**File**: `ExploringGame\Testing\TestMaps.cs`

Add new test infrastructure:
- Create `SkyDomeTest()` method (similar to existing `SkyboxTest()`)
- Create `SkyDomeTestWorldSegment` class that returns `SkyDome.Instance` as its Skybox
- Create `SkyDomeTestRoom` class with appropriate dimensions
  - Similar structure to SkyboxTestRoom
  - Use `OmitSides = Side.All & ~Side.Bottom` to show only floor
  - Dimensions should be appropriate for viewing the dome (e.g., 20x20x10)

## Step 5: Update Program.cs for Testing
**File**: `ExploringGame\Program.cs`

- Comment out the current test map call (`TestMaps.SkyboxTest()`)
- Add call to new test map: `TestMaps.SkyDomeTest()`
- This allows manual testing of the sky dome implementation

## Step 6: Verify Texture Asset Exists
**Location**: Content/Graphics directory (or equivalent)

- Ensure the "sky" texture graphic file exists in the content pipeline
- Verify it's included in the appropriate texture sheet
- If missing, may need to add it or use placeholder

## Step 7: Build and Test
- Run build to check for compilation errors
- Launch the game with the SkyDomeTest map
- Verify:
  - Dome shape is visible (hemisphere, not full sphere)
  - Texture wraps horizontally
  - Texture doesn't repeat vertically
  - Dome rotates with camera but doesn't translate
  - No bottom hemisphere visible

## Step 8: Refinement (if needed)
- Adjust dome segments parameter for better/worse quality
- Fine-tune texture mapping if wrapping isn't correct
- Adjust dome size if needed (default SkyboxShape is 50x50x50)
- Consider filtering criteria if "bottom half" needs better definition

## Notes
- Follow existing code patterns from TestSkybox for consistency
- Reuse skybox infrastructure (depth buffer settings, rotation-only view matrix)
- Keep changes minimal and focused on dome geometry + sky texture
- The system automatically handles buffer caching and rendering pipeline
